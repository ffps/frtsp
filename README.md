# <p align="center"><img src="assets/icon.svg" /><br />fRTSP — конвертер RTSP > MJPEG для Android</p>

Приложение преобразует RTSP-потоки IP-камер в JPEG-кадры и MJPEG по HTTP. Целевая платформа — старые Android-устройства, включая Android 4.2.1 (API 17), ARMv7.

## Возможности

- Несколько камер одновременно: отдельный процесс FFmpeg для каждой включённой камеры.
- RTSP по TCP; поддерживаются H.264 и HEVC/H.265 в соответствии с возможностями встроенной сборки FFmpeg.
- Настраиваемые Output FPS (1–60) и JPEG Quality (1–100).
- Последний JPEG-кадр каждой камеры хранится в памяти.
- HTTP snapshot и непрерывный MJPEG.
- Watchdog контролирует поступление JPEG-кадров и перезапускает зависший процесс FFmpeg.
- JSON API для состояния, статистики, конфигурации, журнала и управления камерами.
- Basic Auth для API при обращении не с localhost. Видео-маршруты доступны без авторизации для использования в видеостенах и kiosk-клиентах.

## Настройка камер

В разделе Cameras добавляются камеры. Для каждой задаются:

- **Camera Name** — уникальный идентификатор URL: латинская буква в начале, далее a-z, 0-9 и _, до 32 символов.
- **RTSP URL** — полный URL с логином, паролем и путём профиля, например rtsp://view:1234@192.168.2.8:554/1/2. Если схема rtsp:// не указана, приложение добавит её автоматически.
- **Enabled** — запускать ли камеру вместе с сервисом.
- **Output FPS** — частота JPEG-кадров, по умолчанию 1.
- **JPEG Quality** — качество JPEG, по умолчанию 75.

Во время работы сервиса настройки камер заблокированы. Сам экран Cameras остаётся доступен для просмотра.

## HTTP

Порт по умолчанию: 8554. Сервер слушает 0.0.0.0.

Для камеры с именем parking:

| Метод | Адрес | Назначение |
|---|---|---|
| GET | /cam/parking.jpg | Последний JPEG-кадр |
| GET | /cam/parking | MJPEG multipart-поток |

Snapshot возвращает 503 frame_not_ready, пока камера ещё не выдала первый кадр. Неизвестное имя камеры возвращает 404.

Корневой адрес / возвращает короткий JSON с названием приложения и адресом API; HTML-панели нет.

## JSON API

Все ответы JSON форматируются с отступами. API доступно по /api/v1/.

| Метод | Адрес | Назначение |
|---|---|---|
| GET | /api/v1/status | Текущее состояние сервера, порт, CPU (замер раз в секунду), память, процессы FFmpeg и состояние камер |
| GET | /api/v1/stats | Накопительные счётчики, средняя загрузка CPU и статистика FPS камер |
| GET | /api/v1/config | Общая конфигурация и список камер; RTSP-пароли маскируются |
| POST | /api/v1/config | Изменить общие параметры: port, password (переданные поля) |
| GET | /api/v1/camera/{name}/config | Получить конфигурацию одной камеры |
| POST | /api/v1/camera/{name}/config | Изменить конфигурацию существующей камеры |
| PUT | /api/v1/camera/{name} | Добавить камеру |
| DELETE | /api/v1/camera/{name} | Удалить камеру |
| GET | /api/v1/version | Версии приложения и сведения о FFmpeg |
| GET | /api/v1/logs | Последние сообщения приложения и stderr FFmpeg (до 200 записей) |
| POST | /api/v1/camera/{name}/start | Запустить камеру (совместимый псевдоним) |
| POST | /api/v1/camera/{name}/stop | Остановить камеру (совместимый псевдоним) |
| POST | /api/v1/camera/{name}/on | Включить камеру; повторный вызов ничего не перезапускает |
| POST | /api/v1/camera/{name}/off | Выключить камеру; повторный вызов безопасен |
| POST | /api/v1/camera/{name}/restart | Перезапустить камеру |
| POST | /api/v1/cameras/restart | Перезапустить все процессы камер |
| POST | /api/v1/service/restart | Перезапустить процессы камер, не останавливая HTTP-сервер |

Логин Basic Auth: api. Пароль задаётся в главном окне приложения. Запросы с 127.0.0.1 и ::1 не требуют авторизации. Если пароль API не задан, внешние запросы к API запрещены.

Примеры для Linux/macOS или терминала с curl:

~~~bash
curl http://АДРЕС_ПЛАНШЕТА:8554/api/v1/status
curl -u api:ВАШ_ПАРОЛЬ http://АДРЕС_ПЛАНШЕТА:8554/api/v1/status
curl -u api:ВАШ_ПАРОЛЬ http://АДРЕС_ПЛАНШЕТА:8554/api/v1/logs
curl -u api:ВАШ_ПАРОЛЬ -X POST http://АДРЕС_ПЛАНШЕТА:8554/api/v1/camera/parking/on
curl -u api:ВАШ_ПАРОЛЬ -X POST http://АДРЕС_ПЛАНШЕТА:8554/api/v1/camera/parking/off
curl -u api:ВАШ_ПАРОЛЬ -X POST http://АДРЕС_ПЛАНШЕТА:8554/api/v1/camera/parking/restart

# Добавить камеру
curl -u api:ВАШ_ПАРОЛЬ -X PUT -H "Content-Type: application/json" -d '{"url":"rtsp://192.168.2.8:554/1/2","enabled":true,"fps":1,"quality":75}' http://АДРЕС_ПЛАНШЕТА:8554/api/v1/camera/parking

# Изменить параметры камеры (можно передавать только изменяемые поля)
curl -u api:ВАШ_ПАРОЛЬ -X POST -H "Content-Type: application/json" -d '{"fps":2,"quality":80}' http://АДРЕС_ПЛАНШЕТА:8554/api/v1/camera/parking/config

# Получить настройки камеры
curl -u api:ВАШ_ПАРОЛЬ http://АДРЕС_ПЛАНШЕТА:8554/api/v1/camera/parking/config

# Удалить камеру
curl -u api:ВАШ_ПАРОЛЬ -X DELETE http://АДРЕС_ПЛАНШЕТА:8554/api/v1/camera/parking

# Изменить общий порт и пароль API (отсутствующие поля не меняются)
curl -u api:ВАШ_ПАРОЛЬ -X POST -H "Content-Type: application/json" -d '{"port":8555,"password":"abc"}' http://АДРЕС_ПЛАНШЕТА:8554/api/v1/config

curl http://АДРЕС_ПЛАНШЕТА:8554/cam/parking.jpg -o parking.jpg
~~~

Basic Auth не шифрует соединение. Используйте API только в доверенной локальной сети; не публикуйте порт сервера напрямую в интернете. Видео-маршруты не защищены Basic Auth.

## Диагностика

При добавлении камеры через PUT обязательны корректные name (он задаётся в URL) и url. URL без схемы автоматически дополняется rtsp://; fps должен быть от 1 до 60, quality — от 1 до 100. Повторный PUT с существующим именем возвращает 409. POST камеры изменяет только переданные поля; имя в теле, если указано, должно совпадать с именем в URL. Изменения сохраняются и сразу применяются к камере.

GET конфигурации маскирует пароль RTSP. Если отправить обратно неизменённый URL с маской :***@, сохранённые учётные данные останутся прежними. Чтобы изменить RTSP-логин или пароль, передайте полный URL.

POST /api/v1/config принимает port (1–65535) и password. Отсутствующие поля не меняются; пустой password отключает внешний доступ к API. При успешной смене порта HTTP-сервер сразу начинает слушать новый порт. Если новый порт занят, настройки откатываются и возвращается ошибка port_unavailable.

В /api/v1/status находятся только текущие показатели:

- CPU: system_usage_percent — загрузка всей системы по последнему замеру; фоновый замер выполняется раз в секунду, sample_age_ms показывает возраст результата;
- memory — актуальные показатели памяти, считываемые при каждом запросе;
- ffmpeg_processes — число работающих процессов FFmpeg;
- для каждой работающей камеры: state, source_width, source_height, output_fps, frame_age_ms, last_error, last_frame_at и last_error_at.

В /api/v1/stats находятся накопительные показатели с момента запуска сервиса:

- totals: jpeg_frames, ffmpeg_restarts и camera_errors — общие счётчики;
- cpu.average_usage_percent — средняя системная загрузка CPU по секундным замерам; samples — количество учтённых замеров;
- для каждой камеры: frames, restarts, errors, average_output_fps, min_output_fps, max_output_fps, average_frame_interval_ms и max_frame_interval_ms.

Статистика хранится только в оперативной памяти и сбрасывается при перезапуске сервиса. Для расчёта FPS сохраняются только агрегированные суммы, количество и экстремумы интервалов между кадрами, а не история отдельных кадров. /api/v1/logs возвращает последние диагностические сообщения. Учётные данные RTSP маскируются в конфигурации и журнале.

## Watchdog и журнал

Для каждой камеры watchdog проверяет поступление JPEG-кадров каждые 5 секунд. Если новых кадров нет более 30 секунд (в том числе если первый кадр так и не получен после запуска FFmpeg), процесс FFmpeg принудительно завершается, после чего CameraWorker запускает его повторно. Интервал между попытками увеличивается: 2, 4, 8, 16 и затем 30 секунд. После успешного получения кадров короткие интервалы восстановления используются снова.

Журнал приложения и диагностический вывод FFmpeg хранятся в кольцевом буфере оперативной памяти: максимум 300 последних записей. Старые записи автоматически вытесняются; API /api/v1/logs возвращает до 200 последних записей. Сообщения также отправляются в системный Android Logcat. Файловый журнал не ведётся — приложение не выполняет регулярную запись логов во флеш-память. Буфер приложения очищается при перезапуске сервиса.

## FFmpeg

В APK включён ранее собранный исполняемый файл FFmpeg 3.3.2 для Android ARMv7:

app/src/main/assets/ffmpeg-armv7/ffmpeg

Это проверенная сборка с декодерами H.264 и HEVC, MJPEG-кодировщиком, image2pipe и RTSP. Файл копируется в приватный каталог приложения и запускается отдельно для каждой включённой камеры. Пересобирать FFmpeg без необходимости не нужно.

## Сборка APK

Релизная сборка запускается **только при отправке в GitHub тега версии** в формате vX.Y.Z, например:

~~~bash
git tag v0.1.0
git push origin v0.1.0
~~~

GitHub Actions соберёт APK и опубликует его в GitHub Releases под именем fRTSP-X.Y.Z.apk.

Для сборки используется JDK 11 и Gradle 7.6.4. В GitHub Actions можно настроить секреты подписи:

- KEYSTORE_BASE64 — файл keystore в Base64;
- KEY_ALIAS — alias ключа;
- KEYSTORE_PASSWORD — пароль keystore;
- KEY_PASSWORD — пароль ключа.

Если секреты подписи не заданы, будет собран неподписанный release APK, который нельзя устанавливать как обычное подписанное обновление поверх другой сборки.
